# ADR-0016: Documentation site with VitePress, aube and GitHub Pages

- Status: accepted (2026-11-17)

## Context
The user docs are Markdown files in `docs/` that GitHub renders one by one, next to the cobra
pages in `docs/cli/`. There is no getting-started page, no
search, and several features have no user doc at all. The 2026-11-17 audit
([docs-content](../../plan/specs/docs-content.md)) lists the gaps. The owner wants a docs site on a
subdomain of sasskovacs.dev for each of the two sibling tools, built the way jdx builds mise.jdx.dev,
usage.jdx.dev, hk.jdx.dev and aube.sh, with an identity of its own for each tool.

Checked on 2026-11-16 and 2026-11-17:

- mise, usage and hk serve VitePress 1.6.4 (the `generator` meta tag on each live site), and aube's
  docs use the same version. All four install packages with aube and commit `aube-lock.yaml`.
- Material for MkDocs is in maintenance mode, with end of life on 2027-05-05. Zensical, its
  successor, released 0.1.0 on 2026-11-05. MkDocs 2.0 is a pre-release without plugins.
- Starlight is at 0.42 (terragrunt's docs) and has not reached 1.0. Hugo with Hextra (goreleaser)
  needs no Node but looks and works unlike the jdx sites.
- VitePress 1.6.4 is the latest stable (2025-08-05). 2.0 is at `2.0.0-alpha.21`.
- Renovate has no aube manager yet (renovatebot/renovate#44428 is open). jdx regenerates
  `aube-lock.yaml` in a workflow on Renovate branches.
- GitHub Pages serves a project site on its own custom domain when the repository sets one. The
  domain sasskovacs.dev is verified for the `sassdavid` account, and both repositories have their
  subdomain, a CNAME to `sassdavid.github.io` and an approved certificate.

## Decision
- Generator: VitePress, pinned to an exact 1.x version in `docs/package.json`. The site root is
  `docs/`. Internal material stays where it is (`docs/plan/`, `docs/engineering/`,
  `docs/dogfood.md`, and `docs/validation/` where it exists) and is left out with `srcExclude`.
- Package manager: aube, with `aube-lock.yaml` committed in `docs/`. node and aube are pinned in
  `mise.docs.toml` and installed only by jobs that set `MISE_ENV=docs`. The repo root gets no
  Node files.
- Lockfile updates: Renovate updates `docs/package.json`, and an `aube-lock.yml` workflow runs
  `aube install` on `renovate-self-hosted/**` branches and pushes the lockfile with a
  `sassdavid-renovate` App token, so CI runs on that commit. The workflow goes away once Renovate
  ships an aube manager.
- Hosting: GitHub Pages from a GitHub Actions workflow, at `https://<tool>.sasskovacs.dev`
  for each tool, with HTTPS enforced. The custom
  domain lives in the repository's Pages settings, so the site has no `CNAME` file.
- Deploy timing: on release. `release-please.yml` calls `docs.yml` with `workflow_call` after
  the release job, so the site describes the latest released binary. Pull requests build the
  site without deploying. `workflow_dispatch` redeploys a given tag, the latest one by default.
- Content from code: the CLI reference, configuration reference, exit codes, environment
  variables, JSON schemas, MCP tools and each tool's catalogues are generated by Go programs
  under `scripts/`. They are committed, and `mise run docs` fails when they are stale.
- Privacy: no analytics, no third-party requests at runtime. Fonts are self-hosted from
  Fontsource packages and search is VitePress local search.
- Identity: each tool has its own visual identity ([docs-design](../../plan/specs/docs-design.md)).
  The build, generators, workflows and checks are shared between the siblings.

## Reasons
- VitePress matches the sites the owner named, and the jdx repos show working answers for the
  CLI reference, `llms.txt`, social cards, link checks and deploys that can be adapted.
- aube keeps parity with those repos and has the strictest install defaults of the Node package
  managers (lifecycle scripts denied by default, a release-age cooldown). Its one gap, Renovate
  support, has a small workaround with a clear exit.
- Deploying on release keeps the site and the binary in step. Both tools are pre-1.0 and their
  flags still change between releases.
- Keeping internal docs in place leaves every link in CLAUDE.md, the rules, specs and milestones
  unchanged.

Not adopted:

- Starlight: a good second choice with more frequent releases, but it is pre-1.0 and further from
  the jdx structure.
- Hugo with Hextra: no Node toolchain, but a different look and fewer working references for this
  structure.
- MkDocs Material and Zensical: end of life in 2027, and too new, respectively.
- Docusaurus: its strength is versioned docs, which neither tool needs.
- pnpm, or aube writing `pnpm-lock.yaml`: full Renovate support, but less parity with jdx, and in
  the second case two tools would rewrite one lockfile.
- Deploying from main: the site would show unreleased flags as available.

## Consequences
- The docs job needs node and aube. Go jobs and goreleaser don't.
- VitePress 2.0 will need a migration once it is stable. jdx's sites face the same change.
- `docs/package.json`, `docs/aube-lock.yaml`, `mise.docs.toml` and the new workflows join the
  sibling lists. `mise.docs.lock` holds the tool checksums, and oxfmt, an npm tool, also has its
  aube lockfile under `.mise/locks/`. Theme colours, fonts and home components differ per tool on purpose.
- Help texts and runtime messages link to site URLs instead of repo paths.
- The `aube-lock` environment holds a second copy of the Renovate App key, limited to
  `renovate-self-hosted/**` branches, because the `renovate` environment only allows `main`.

# tfcensus: testing plan (no AWS account required)

The shared layers are in [engineering ADR-0006](../engineering/adr/0006-testing-strategy.md).
**Constraint (2026-11-09):** there's no sandbox AWS account. Development and CI must run with **zero AWS accounts**.
Real-account validation is an optional later phase ([§ Later](#later-real-aws-validation-optional)).
Research basis: emulator coverage was checked API by API against tfcensus's call list.

## Layers

| Layer | Runs | Tools | Covers |
|---|---|---|---|
| **L0 unit** | every PR, no Docker | interfaces + hand-written JSON/XML fixtures from AWS API docs / botocore shapes; go-vcr cassettes | domain logic; **the only coverage for Config `Select*`/aggregator SQL results** (no emulator executes Config SQL) |
| **L1 in-process** | every PR, no Docker | `johannesboyne/gofakes3` v1.2.0 (in-process S3 with conditional put); `sivchari/kumo` v0.33.1 (Go, `httptest`-style AWS emulator) | state read/write/lockfile, `move` push/rollback against versioned buckets; basic EC2/IAM/Route53/KMS. kumo lacks DescribeSecurityGroupRules, GetBucketReplication and GetBucketOwnershipControls, so those use L0 fixtures |
| **L2 containers** | every PR (Linux runners), `testcontainers-go` v0.45.0 | **moto** `motoserver/moto:5.2.5` (Apache-2.0) | broad coverage: EC2 SG/SG rules/ENIs, IAM, Route53, all S3 bucket-config ops, DynamoDB, KMS, Organizations, STS AssumeRole. **Multi-account** via AssumeRole (account taken from the role ARN) or the `x-moto-account-id` header. Per-region state. Reset with `POST /moto-api/reset` |
| | | **Floci** 2.4.0 (MIT, young, 2026-02) | the **only** emulator with Resource Explorer 2 (all 32 APIs, live, no indexing lag) and Cloud Control List/Get backed by real service state (17 types). Config recorders without `Select*`. Treat as "verify fidelity" |
| **L3 e2e** | nightly + manual | terraform 1.17 / tofu 1.13 / terragrunt 1.2 against moto | the full loop: S3 backend with `endpoints`, `use_path_style`, `use_lockfile`; apply a fixture → mutate via SDK → `plan -refresh-only` shows drift; `state pull/push`; `move` surgery + rollback |

### How the code stays emulator-friendly
- No endpoint special-casing in product code. aws-sdk-go-v2 honours `AWS_ENDPOINT_URL` / `AWS_ENDPOINT_URL_<SERVICE>`, and S3 needs `UsePathStyle` (enabled when a custom S3 endpoint is set).
- Retries are disabled in tests (`retry.AddWithMaxAttempts(…, 1)`), so failures surface immediately.
- **Stubs sit at the HTTP layer**, not the Finalize middleware. Use `aws.Config.HTTPClient` → an httptest server or a go-vcr recorder. This exercises the real deserializers, paginators and error codes. Finalize stubs skip deserialization and hide bugs.
- go-vcr matcher: the shared `internal/testutil/vcr` scrubber matches method, URL and body and ignores headers, except the ones in `Scrubber.Match`. `awstest.Scrubber()` adds **`X-Amz-Target`**, because Config, Organizations and Cloud Control all POST to `/`. Its save hook drops `Authorization`, `X-Amz-Security-Token`, `X-Amz-Date`, the SDK headers and credential fields, and replaces account IDs with `111111111111` while recording.
- The AWS cassettes in `testdata/cassettes/aws/` are written from AWS API reference response shapes, not recorded from an account, and the tests only replay them.

## Fixtures
- **Terragrunt fixture repos** in `testdata/repos/` (`tg-live/`, `tg-multi-account/`, `plain-tf/`). Inspired by the local terragrunt-infrastructure-live-stacks-example ([reference-repos.md](reference-repos.md)).
- **Fake `terragrunt`** (`internal/testutil/fakebin`): replays recorded `find`/`render`/`run --all`/`state pull|push` output and logs argv. Used in L0/L1. `scripts/record-terragrunt.sh` records the output from the real binary into `testdata/terragrunt/`. The real binary is used in L3.
- **States:** TF 1.5 (no identity), TF 1.12+ (identity), OpenTofu encrypted, workspaces, a 50 MB synthetic state, empty states, a duplicate-lineage pair. Generated by L3 runs against moto, then frozen.
- **Config items:** real-shaped items (ENIs, ASG/Karpenter instances, CloudFormation-tagged resources, default VPCs) for the ownership packs.
- The typemap is generated from local `terraform-provider-aws` and `terraform-provider-awscc` clones. `typemap:gen` reads `TFCENSUS_PROVIDER_AWS_DIR` / `TFCENSUS_PROVIDER_AWSCC_DIR`, defaulting to `~/src/github/_reference/hashicorp/<repo>`, and records each clone's commit in the generated data header.

## Gaps only real AWS can validate (tracked as `docs/validation/TODO.md`)
- Config SQL dialect, limits and aggregator authorization/lag. Real recorder setups: the Control Tower baseline recorder, periodic recording, excluded types, unrecorded regions.
- Resource Explorer indexing lag (minutes; up to 2 h untagged; up to 36 h aggregator), unsupported types, view filters.
- Cloud Control parent-required types, `UnsupportedActionException`, per-type property shapes.
- Real throttling, adaptive-retry behaviour, eventual consistency, performance at scale.
- Access-denied realities: SCP explicit denies, KMS key policies, SSE-KMS state, S3 wrong-region 301s, cross-account roles, IAM Identity Center/SSO flows.
- Provider vs API divergence in refresh-only plans.

## Later: real-AWS validation (optional)
1. **Read-only runs on existing non-prod work accounts** (manual, with named profiles approved per session):
   - use a read-only role: ViewOnlyAccess + `config:Select*`, `resource-explorer-2:Search|List*|Get*`, `cloudformation:ListResources|GetResource`, and `s3:GetObject` + `kms:Decrypt` scoped to state buckets;
   - **check employer policy first**: state contains secrets, and tfcensus prints only identifiers;
   - record redacted cassettes during these runs. They become the realistic L0 fixtures. **Never run `move` there.**
2. **A dedicated sandbox, if ever needed** (for `move` e2e on real S3, and experimenting with Config/RE setups):
   - a member account in an Organization (Sandbox OU, SCP region/service allowlist, budget action);
   - or the 2025 AWS Free Plan ($100–200 credits, auto-suspends after 6 months or when credits run out).
   - Config bills per recorded item, so limit the recorded types. RE and Cloud Control reads are free.
3. **CI against real AWS**, only when (2) exists: a scheduled GitHub OIDC job assuming the read-only role, `sub` pinned to `main` or a protected environment, never on fork PRs.

## Not used (and why)
- **LocalStack:** since 2026-03-23 the image needs an auth token, and the community repo is archived. The free OSS program excludes projects owned by for-profit entities. Its Config is mocked and it has no Resource Explorer.
- **MinIO:** archived 2026-04-25, and its images were removed.
- **dynalite:** stale. Use DynamoDB Local only if DynamoDB-lock tests are needed (DynamoDB locking is deprecated in Terraform).

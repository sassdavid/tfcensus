# Spec: documentation site

The public docs site at `https://tfcensus.sasskovacs.dev`: how it is built, what is generated
from code, how it deploys and which checks keep it true to the released binary. The design
is in [docs-design](docs-design.md) and the page list in [docs-content](docs-content.md).
Decisions: engineering [ADR-0016](../../engineering/adr/0016-docs-site.md). The sibling repo has
the same spec with its own name, and the parts marked "shared" must stay the same in both repos.

## Goals

- A user gets from "what is this" to a first read-only run in one page, then finds every
  command, flag, config key, exit code and output format in the reference.
- Every fact that code can state is generated from code and checked for staleness, so the site
  can't describe flags that don't exist.
- The site describes the latest release, never unreleased behaviour.
- The structure follows the jdx sites (mise, usage, hk, aube). Text, styling and assets are our
  own.

## Non-goals

- Versioned docs per release. The site always shows the latest release, and the changelog page
  covers older ones.
- Translations.
- Analytics, comments, ads or any third-party script.
- Publishing `docs/plan/`, `docs/engineering/`, `docs/dogfood.md`, or `docs/validation/` where
  the repo has it.

## Layout (shared)

```
docs/
  package.json            vitepress (exact), vue, @fontsource packages, @resvg/resvg-js
  aube-lock.yaml
  aube-workspace.yaml     minimumReleaseAge matching renovate.json (3 days)
  README.md               contributor guide for the site (srcExclude)
  index.md                layout: home, one custom component
  getting-started.md  install.md
  guides/  concepts/      hand-written pages
  reference/              generated pages plus hand-written framing
  cli/                    GENERATED by scripts/gendocs, nested by command path, plus commands.json
  public/                 glyph.svg, favicons, site.webmanifest, llms.txt (GENERATED),
                          schemas/*.json (GENERATED copies of schemas/)
  .vitepress/
    config.mts            site config (similar per tool)
    sidebar.mts           hand-written sections plus the CLI tree from cli/commands.json
    llms.mts              llms.txt generator (shared)
    social.mjs  social-check.mjs   build-time social cards and their check (shared)
    fonts/                OFL font file for social cards plus <name>.LICENSE (ADR-0012)
    theme/
      index.ts            extends the default theme, registers components (shared shape)
      tokens.css          colours, fonts, spacing (per tool, from docs-design)
      components/         per tool (home, marks, transcript)
  plan/ engineering/ dogfood.md (validation/)  internal, srcExclude
mise.docs.toml            node, aube, lychee and oxfmt pinned exactly for MISE_ENV=docs
```

`docs/ci/*.yml` stay where they are. jactionlint checks them, and the CI guide embeds them
verbatim with VitePress `<<<` includes.

## Toolchain (shared)

- node 26.13.1 (the current LTS line) and aube 2.10.1, both in `mise.docs.toml` with
  `mise.lock` entries. CI uses `jdx/mise-action` with `MISE_ENV=docs`. No `setup-node`.
- VitePress 1.6.4, pinned exactly. Renovate's npm manager updates `docs/package.json` and the
  `aube-lock.yml` workflow refreshes the lockfile.
- CI installs with `aube install --frozen-lockfile`. Lifecycle scripts stay denied, except the
  packages `aube` reports as needing them, and those are listed in `aube-workspace.yaml` with a
  reason.
- oxfmt formats `.mts`, `.ts`, `.vue` and `.css` under `docs/.vitepress`, with the generated
  paths ignored. `mise run lint:docs` runs `oxfmt --check`.
- lychee checks links in the built site.

## Site configuration (shared shape)

- `title` and `description` from the tool, `lang: "en"`, `cleanUrls: true` (GitHub Pages serves
  `/x` for `/x.html`), `lastUpdated: true` (checkout with full history), `sitemap.hostname` set to
  the site URL.
- `srcExclude`: `plan/**`, `engineering/**`, `validation/**`, `dogfood.md`, `README.md`, and in
  M22 only `cli/**` until M23 generates the new reference. A pattern with no match is harmless.
- Search: `provider: "local"`.
- `editLink` to `github.com/sassdavid/tfcensus/edit/main/docs/:path`, turned off on generated
  pages with frontmatter `editLink: false`.
- Nav: Guide, Reference, CLI, a version item that reads `.release-please-manifest.json` and links
  to the changelog page, and GitHub. The footer is a theme component in `layout-bottom` with
  license and source links and no sponsor or newsletter blocks.
- `transformPageData` fails the build when a page has no frontmatter `description` (mise does
  this), because search, social cards and `llms.txt` use it.
- `transformHead` writes canonical, Open Graph and Twitter tags from title, description and the
  page's social card.
- Dead links: VitePress fails the build on dead internal links by default. Leave that on.

## Generated content (shared generators)

All generators are Go programs. They build the cobra tree with `cli.NewRootCmd`, as
`scripts/gendocs` already does, and write files that are committed. `mise run docs` regenerates
everything and exits 1 when a file changed. CI runs it.

### CLI reference

`scripts/gendocs` stops using `doc.GenMarkdownTree` and writes the site pages itself:

- One page per non-hidden command at `docs/cli/<path>.md`, for example `docs/cli/config/show.md`
  served at `/cli/config/show`. Group commands get `index.md` in their folder. The root page is
  `docs/cli/index.md`.
- Frontmatter: `title: "tfcensus config show"`, `description:` from `cmd.Short`,
  `editLink: false`, and a comment line saying the file is generated by `scripts/gendocs`.
- Page body, in this order: one `#` heading, the description, the usage line in a `sh` block,
  aliases, arguments, a flags table, accepted `--format` values, `--fail-on` values where the
  command has them, exit codes, examples from `cmd.Example`, subcommands with their descriptions,
  and a "Related" list from `cmd.Annotations["docs.related"]`.
- Flags table columns: flag (with shorthand), type, default, values (from the completion
  registry choices with their descriptions), config key (from `flagKeys()`), and notes for
  required or mutually exclusive flags (cobra's flag annotations). Bool flags print as `--force`,
  never `--force[=true|false]`.
- Global flags appear once, on `/cli/global-flags`, and every page links there.
- `Long` text is escaped for Vue: `<word>` outside code becomes `&lt;word&gt;`, and `{{` is
  wrapped in `v-pre`. Blocks indented two or more spaces become fenced `text` blocks, so the
  tables in help text keep their shape.
- The shell completion commands collapse into one page, `/cli/completion`, with a table of
  shells.
- `docs/cli/commands.json` holds the tree (`name`, `path`, `short`, `hidden`, `children`) for
  `sidebar.mts`.
- The manpages keep using `GenManTree`, unchanged.

Per-command metadata lives on the command, so no generator parses Go source:

- `Annotations["formats"]`: the accepted `--format` values. A test runs each command with every
  format and checks that the listed ones are accepted and the others exit 2.
- `Annotations["fail-on"]`: the accepted gate values, tested the same way.
- `Annotations["exit-codes"]`: the codes the command returns. A table next to the constants in
  `internal/cli/run.go` gives each code a description, and a test checks that every `exitError`
  code in a command's code is listed.
- `Annotations["docs.related"]`: guide and concept paths, checked against the built site.

A test fails when a non-hidden command lacks `Long` or `Example`, except for an allowlist with
reasons (group commands, completion shells).

### Configuration and environment

- `/reference/config` comes from `schemas/config-v1.json`, `config.Default()`,
  `config.EnvVarName` and the reverse of `flagKeys()`: key, type, default, allowed values, env
  var, the flag that sets it, and the description. A test fails when a schema leaf has no
  `jsonschema_description`, or when a `flagKeys` value is not a schema key.
- The page also includes the `config init` template from `internal/config/template.yaml`.
- `/reference/environment` lists every variable the code reads. A test greps non-test Go
  sources for `os.Getenv`, `os.LookupEnv` and the koanf prefix, and fails when a name is missing
  from the page or from an allowlist of test-only names (`TEST_CASSETTE`, `GOLDEN_UPDATE` and
  the like).

### Exit codes, schemas and MCP

- `/reference/exit-codes` from the table in `run.go`, plus the per-command lists.
- `/reference/schemas` lists `schemas/*.json`. The build copies them to `docs/public/schemas/`,
  served at `/schemas/<name>.json`. A test checks that each schema's `$id` equals its served URL.
- `/reference/mcp` starts `mcpserver.New` in process with a stub backend, calls `tools/list` and
  `prompts/list`, and renders names, titles, descriptions and input schemas. A golden test covers
  the output.

### Docs URLs in the binary

A shared `docsurl` helper builds `https://tfcensus.sasskovacs.dev/<path>`. Help texts, runtime
messages and the `config init` template use it instead of repo paths such as
`docs/install.md`. A test collects every path passed to the helper and checks that the
built site has the page.

### Snippet checks

- Every `tfcensus ...` command line in site Markdown (fenced `sh` blocks and inline code) is parsed
  against the cobra tree. Unknown commands, flags or enum values fail the check.
- Every config key in backticks on the config, guides and concepts pages exists in the schema.
- Output examples come from test goldens through `<<< @/../testdata/golden/...` includes, so
  `mise run test:golden -- -update` updates the site too. No output on the site is typed by hand.

### llms.txt

`docs/.vitepress/llms.mts` writes `docs/public/llms.txt` from the sidebar and each page's
`description`, in the llmstxt.org format: the title, a summary, then one section per sidebar
group with a link and description per page. It is committed and checked for staleness like the
other generated files.

## Deploy (shared)

```
push to main ─> release-please.yml ─> release created? ─> release.yml (goreleaser)
                                                  └──> docs.yml (workflow_call, tag)
                                                          build at the tag ─> deploy-pages
pull_request (docs/**, scripts/gendocs/**, internal/cli/**, schemas/**) ─> docs.yml: build only
workflow_dispatch (ref, default: latest release tag) ─> docs.yml: build and deploy
```

- `docs.yml` has `permissions: {}` at the top. The build job has `contents: read`; the deploy job
  has `pages: write` and `id-token: write` with `environment: github-pages`.
  `concurrency: { group: pages, cancel-in-progress: false }`. Every action is pinned by SHA, and
  every job has `timeout-minutes`.
- The build job checks out the tag with `fetch-depth: 0` and `persist-credentials: false`, then
  runs `mise run docs` (stale check), `mise run docs:build` and the checks below, then uploads
  `docs/.vitepress/dist` with `actions/upload-pages-artifact`.
- Doc-only fixes on main reach the site with the next release, or through `workflow_dispatch`
  with `ref: main` when the owner decides the change describes released behaviour.
- `aube-lock.yml` runs on pushes to `renovate-self-hosted/**` by the Renovate App. It runs
  `aube install` in `docs/` and commits `aube-lock.yaml` through the API with a token from the
  `sassdavid-renovate` App, stored in an `aube-lock` environment whose deployment branches are
  `renovate-self-hosted/**`.
- The repository's Pages settings: source "GitHub Actions", custom domain set, "Enforce HTTPS" on.

## Checks (shared)

`mise run docs:build` runs, in order:

1. The generators' stale check (`mise run docs`).
2. Unit tests for `llms.mts`, `social.mjs` and the contrast check.
3. `vitepress build docs` (fails on dead internal links, Vue compile errors and a missing
   `description`).
4. The social card check: every page has a card file and matching meta tags.
5. `lychee --offline --include-fragments docs/.vitepress/dist` for internal links and anchors.

Elsewhere:

- `mise run lint:prose` covers every published page. It already skips `docs/plan`. A test makes
  sure it doesn't skip the published folders.
- The repo's grep tests for data that must never be printed (state attribute values, tokens)
  also run on the site sources and the built site.
- A test fails when a published page links into `plan/`, `engineering/` or `validation/`.
- The contrast check reads `tokens.css` and fails when a text token is under 4.5:1 or a graphic
  token under 3:1 against the surfaces it is used on, in both themes.
- Accessibility: `@axe-core/cli` (or pa11y-ci) runs on the built home page, a guide, a CLI page
  and the config reference in both themes, with no violations at WCAG 2.2 AA.
- jactionlint checks `docs.yml` and `aube-lock.yml`.

## Acceptance criteria

1. `mise run docs:build` passes locally and in CI, from a clean checkout, with only
   `MISE_ENV=docs mise install` and `aube install --frozen-lockfile` before it.
2. A release created by release-please deploys the site at that tag, and
   `curl -sI https://tfcensus.sasskovacs.dev/` returns 200 while the `http://` URL redirects to
   `https://`.
3. A pull request that changes a flag without running `mise run docs` fails CI.
4. Every non-hidden command has a page under `/cli/`, with the sections listed above, and no page
   shows `[=true|false]` or a raw `<word>` outside code.
5. The config, environment, exit-code, schema and MCP reference pages are generated, and each has
   a test that fails when code and page disagree.
6. No help text, runtime message or config template points at a repo path for user docs.
7. The snippet check finds no unknown command, flag, enum value or config key on the site.
8. `llms.txt`, the sitemap and a social card exist for every page, and the checks pass.
9. Lighthouse accessibility is 100 and best practices at least 95 on the home page and a CLI
   page, and axe finds no WCAG 2.2 AA violation.
10. The site makes no request to a third-party host (checked in the built HTML and JS: no
    external `src`, `href` to fonts or scripts, or `fetch` to another origin).
11. `mise run sibling:diff` passes in both repos.

# Spec: docs site content (tfcensus)

What the site at `https://tfcensus.sasskovacs.dev` contains, where each page gets its facts, and
which statements in today's docs and help texts are wrong. The build and generators are in
[docs-site](docs-site.md), the design in [docs-design](docs-design.md).

The audit behind this spec ran on 2026-11-17 against `main` after v0.4.0. It read every command
in `internal/cli`, the Config struct, the schemas and the user docs, and regenerated `docs/cli`
to confirm the checked-in copy was current. Code wins wherever code and docs disagree. Each
milestone that writes pages reruns the parts of the audit it touches, because file and line
references go stale.

## Structure

The sidebar follows Diataxis: a tutorial to start, how-to guides, concepts (explanation) and
reference. Kind: Gen = generated by a Go program, Hand = written by hand, Port = moved from an
existing doc and rewritten to the writing rules.

## Gaps: features with no user doc

Each is covered by the page named in the structure above.

- Ownership rules: CEL fields, `in_state()`, packs and the category each sets, guards,
  `never_hide`, `expires`, rule IDs. Today only `docs/plan/specs/ownership-rules.md`, and the
  `config init` template points users there (`internal/config/template.yaml`).
- The 25 backend audit checks and their severities; suppressions beyond the help text.
- Drift noise presets (`aws-tags-all`, `computed-hashes`) and `drift.noise`.
- Config keys with no prose: `scan.external_dns`, `accounts.aggregator`,
  `scan.cloudcontrol_types`, `scan.never_hide`, `scan.packs.*`, `audit.policy.*`.
- Environment rules: maps and object lists can't be set from env, `-` becomes `_` as well as
  `.`, and unknown `TFCENSUS_*` variables only warn.
- Child processes such as terragrunt get only allow-listed environment variables
  (`internal/execx`). A terragrunt config that reads a custom variable sees nothing.
- State is read from `s3` backends only (`internal/tfstate/reader.go`).
- `AWS_ENDPOINT_URL` path-style behaviour, `SSL_CERT_FILE` for notify, `CI` turning prompts off,
  exit 130.
- Flags with no prose: `scan --explain-coverage`, `scan --explain`, `whois --stdin`,
  `codify --select`, `--log-format json`, `--log-file`, `--decrypt-with-tofu`,
  `--generate-stacks`, and `cache info|clear`.
- Inventory layer names (`native:*`) and the rule IDs listed above.
- The JSON output contract: envelope fields, `schema_version`, which commands have schemas.
- Type mapping coverage: which Terraform types are mapped and which stay `undetermined`.
- Supported tool versions (today only in `docs/engineering/version-policy.md`).
- tfcensus-action inputs and outputs (today only in the action repo's README).

## Gaps: generated `docs/cli`

Fixed by the generator in [docs-site](docs-site.md#cli-reference):

- cobra file names (`tfcensus_audit_backend.md`), `##` as the top heading, no frontmatter.
- The 11 global flags repeated on every page.
- `--force[=true|false]` on every bool flag.
- Raw `<tmp>`, `<arn|id>`, `<key>`, `<unit>` and others outside code in 9 files, which VitePress
  would compile as Vue tags.
- Indented tables in help text that Markdown folds into one paragraph (scan categories, doctor
  layers, notify targets, MCP tools, config layers, the cache table).
- `Long` missing on version, config path, config show, cache info, cache clear, audit, rules.
  `Example` missing on root, audit, cache, cache info, cache clear, completion, config,
  config path, move, report, rules.
- 11 completion pages, empty Options blocks on group pages, no required or exclusive flag
  markers, `--format` listing all seven values on every command.

## Never on the site

- State attribute values, real account IDs, bucket names, ARNs, unit paths and AWS profile
  names. Examples use the fixture names (`acme-*`) and IDs (`111111111111`) the tests use. The
  real profile name in `docs/dogfood.md` and `docs/validation/backend-audit.md` stays out.
- Secrets or token values. Notify examples use `${{ github.token }}` and placeholder webhook
  variables.
- Internal material: `docs/plan/`, `docs/engineering/`, milestone names, CLAUDE.md,
  `.claude/rules/`. User-relevant decisions (read-only by default, no built-in LLM, version
  policy) are rewritten as concept pages.
- Test-only variables and internals: `TEST_CASSETTE`, `GOLDEN_UPDATE`, fakebin, cassettes, the
  hidden `_carapace` command.

## Acceptance criteria

1. Every page in the structure exists with a `description`, or the milestone that owns it lists
   it as moved to a later one.
2. Every item under "features with no user doc" is covered by a page.
3. Every row under "wrong or stale statements" is fixed in code or docs, with the commit named in
   the milestone evidence.
4. The never-on-the-site checks (grep test, link rule, profile-name grep) pass on the built site.
5. README keeps a short introduction, the install command and links to the site, and no longer
   carries guide content.
